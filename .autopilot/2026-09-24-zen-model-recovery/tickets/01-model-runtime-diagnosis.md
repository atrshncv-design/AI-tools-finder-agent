# 01 — Диагностика доступности выбранной Go-модели

**Требования:** G01, R01, R02, R03
**Blocked by:** —
**Зона:** `remote-model-diagnosis`, `pipeline-config`
**Волна:** 1
**Status:** ready

## Что должно заработать

Read-only проверка должна установить, доступна ли фактически настроенная Go-модель для runtime chat completions, и дать безопасный следующий шаг без автоматической смены production.

## Из брифа, дословно

> «продолжи работу»

Контекст продолжения зафиксирован в спецификации: после ручного обновления production каталог содержит выбранную модель, но runtime сообщает `Model is unavailable`.

## Разделы спецификации

Задача; Решения; пользовательские истории 1–4; Границы и швы; Вне рамок; Покрытие манифеста.

## Критерии приёмки

- [ ] Проверены effective endpoint, наличие ключа и длина без вывода значения, configured model и модель из каталога.
- [ ] Выполнен один минимальный completion-probe; в evidence остаются только HTTP-класс, фактический model id и безопасная классификация ошибки.
- [ ] Сопоставлены каталог, process environment и runtime error.
- [ ] Причина доказана либо явно отмечена как не доказанная; автоматический fallback не добавлен.
- [ ] Production не изменён.
- [ ] Итог содержит отдельный безопасный next action и не содержит credentials.
