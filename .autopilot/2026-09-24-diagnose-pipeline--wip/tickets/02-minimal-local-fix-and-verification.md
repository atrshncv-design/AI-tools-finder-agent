## Что должно заработать

Если тикет 01 докажет причину в коде или конфигурации репозитория, будет внесено минимальное исправление в затронутый слой. Если причина production-only, будет оформлен BLOCKED/next action без изменения production. При наличии воспроизводимого сценария добавляется узкий регрессионный тест; pipeline-документация синхронизируется только при изменении pipeline logic.

## Разделы спецификации

Пользовательские истории R07–R08; решения «Правила исправления» и «Безопасность»; границы `pipeline-code` и `evidence-report`.

## Критерии приёмки

- [ ] Изменение ограничено доказанной причиной и не содержит новых секретов/провайдеров/рефакторинга.
- [ ] Для изменённой production pipeline logic обновлён `app/skills/news-processor/SKILL.md`.
- [ ] Добавлен узкий тест на воспроизведённый сценарий либо документирована невозможность теста.
- [ ] `cd app && npx tsc -b` завершился успешно.
- [ ] `cd app && npx vitest run` завершился успешно; результат сохранён без секретов.
- [ ] Production не изменён; commit возможен только после зелёных gates и redaction check.
