# Спецификация: корректные даты, строгие разделы и прочитанность дэшборда

## Контекст

По обратной связи клиента в дэшборде наблюдаются четыре связанных класса дефектов:
1. фильтр «За сутки» показывает материалы с неожиданными датами и список не идёт по свежести;
2. «ИИ для науки» содержит общенаучные материалы без ИИ-составляющей;
3. «Инструменты для изобретений» смешивает каталог ИИ-инструментов с обычными новостями;
4. открытая новость иногда остаётся визуально непрочитанной после возврата.

## Решения пользователя

- «За сутки» означает скользящие последние 24 часа.
- Окна свежести и порядок выдачи используют `updatedAt` — дату появления/обновления материала в агенте.
- На карточке показывается только дата добавления/обновления в агенте, без второй даты источника.
- «ИИ для науки» содержит только материалы с явной связью с AI/ML/нейросетями или применением ИИ в научном процессе.
- «Инструменты для изобретений» содержит только реальные ИИ-инструменты для создания, исследования или проверки изобретений, с официальной ссылкой и описанием применения. Обычные новости туда не входят.
- Материал становится прочитанным при успешном открытии страницы материала; прямое открытие и возврат кнопкой «Назад» должны давать одинаковый результат.
- Разделение на три отдельных Telegram-бота не входит в эту задачу.

## Объём работ

### 1. Даты, фильтры и сортировка

- Привести API-выдачу новостей к единому правилу: freshness filter и `ORDER BY` используют `updatedAt DESC` с детерминированным tie-breaker по `id DESC`.
- Привести карточки новостей и карточки каталога к отображению той же даты `updatedAt`/эквивалентной даты обновления каталога, которая участвует в фильтре.
- Сохранить URL-состояние фильтров при переходах и возврате.
- Проверить окна `day`, `3days`, `week`, `month` и отсутствие будущих дат.

### 2. Строгая классификация науки

- Убрать fallback, который отправляет любую общенаучную статью в science.
- Для science требовать одновременно научную область и явный AI/ML-сигнал в заголовке/описании/извлечённом содержимом.
- Сохранить существующие научные поля и типы классификации для прошедших gate.
- Добавить тесты на позитивные и негативные примеры: AI + biology/chemistry/materials проходит; награда, визы, биография или общий научный текст без AI не проходит.
- Для уже сохранённых строк предусмотреть безопасный reclassification/backfill script или SQL-процедуру без выдуманных данных; не удалять материал, а переводить его в корректный раздел/статус по существующей доменной логике.

### 3. Строгий каталог ИИ-инструментов

- Не объединять `news.list(section=invention-tools)` с каталогом `invention_tools` на странице инструментов.
- Источник карточек раздела — только `invention_tools`.
- На уровне записи/seed/evaluation закрепить критерий: инструмент должен быть AI-инструментом для изобретательской/научно-инженерной работы, иметь валидную официальную `http(s)`-ссылку и непустое описание.
- Удаление/исправление существующих ошибочных каталоговых записей выполнять только по проверяемым данным; не создавать фиктивные записи.
- Счётчик раздела должен совпадать с количеством видимых каталоговых карточек после sphere/freshness фильтров.

### 4. Прочитанность

- Сохранить отметку прочитанного при открытии detail page.
- Сделать действие устойчивым к повторному рендеру, React Strict Mode, повторному возврату и обновлению кэша.
- После успешной мутации инвалидировать список статусов и оба вида unread counters; визуальный синий маркер должен исчезать после возврата в список.
- Не менять поведение для неавторизованных пользователей: личный read-status не создаётся.

## Не входит в объём

- Разделение на три Telegram-бота.
- Изменение дизайна карточек или возврат к старому английскому виду.
- Массовое редактирование текстов новостей без подтверждённого источника.
- Деплой на production и рассылка Telegram без отдельного подтверждения.

## Проверка готовности

- `cd app && npx tsc -b`
- `cd app && npx vitest run`
- Тесты API проверяют фильтр и порядок по `updatedAt`.
- Тесты классификатора покрывают нерелевантные примеры из обратной связи.
- UI/компонентные тесты либо существующие интеграционные проверки подтверждают открытие, отметку read, возврат с сохранённым фильтром и корректный счётчик каталога.
- Перед финальным отчётом проверить `git diff`, `PROGRESS.md` и статус всех тикетов.
