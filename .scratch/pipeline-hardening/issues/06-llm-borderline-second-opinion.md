# Тикет 06: LLM-второе-мнение для пограничных статей (нужно решение по бюджету)

Status: cancelled
Blocked by: 01-observability-health-line.md

## Проблема

Словарные классификаторы достигли потолка: остаточный шум ~2–3%
(«лечение багов», «робототехники», «организм» в философском эссе,
случайные «квантовые» в эссе). Дальнейшая чистка словарей даёт
убывающую отдачу и рискует порезать реальные кейсы.

## Что сделать (после решения владельца по токен-бюджету)

- В `evaluate-news.ts`: для статей с итоговым score в «пограничной зоне»
  гейта (например, 45–70) — один лёгкий вызов Zen с вопросом-класификатором:
  «Связана ли новость с ИИ/ML? Относится ли к науке/изобретениям? JSON
  {ai: bool, science: bool, invention: bool}». Ответ уточняет секцию и
  может отклонить статью вопреки словарям (но не поднять ниже гейта).
- Вызывать только для статей, прошедших жёсткий ИИ-гейт — это ~5–15 вызовов
  за цикл на текущем объёме.
- Кэш вердикта в `metrics.llmClassify` (не спрашивать дважды), таймаут и
  fail-open (LLM недоступна → словарное решение остаётся).
- Оценка бюджета: ~10 вызовов × 24 цикла × ~500 токенов ≈ 120K токенов/сутки
  free-моделью — доложить фактические цифры после недели работы.

## Acceptance criteria

- Пограничные статьи получают уточнённую секцию; отказ Zen не ломает цикл.
- В дайджест-строке здоровья видно число LLM-уточнений за сутки.

## Закрыто владельцем (26.08.2026)

«Эти вопросы закрываем» — LLM-второе-мнение реализовывать не будем.
Словарные классификаторы остаются финальным решением; остаточный шум ~2–3%
принят как есть.
