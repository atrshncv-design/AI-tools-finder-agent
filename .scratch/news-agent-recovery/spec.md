# Спека: восстановление дайджеста и чистка данных (recovery-20260820)

## Контекст (факты, 2026-08-20)

Клиент получил утренний дайджест с тремя дефектами:
1. Превью статей — «название + теги» вместо «название + краткое описание»
2. В разделы ИИ-новости / ИИ для науки / Инструменты попал мусор без ИИ
   (косатки, премия Филдса, визы, некрологи — nature.com d41586)
3. Дашборд «За сутки» показывал июльские статьи

Корневые причины установлены:
- A. Коммиты `3b9d7c7..7b31b25` (строгий классификатор, каталог инструментов,
  фильтр updatedAt, формат превью) были в git, но НЕ развёрнуты на сервер.
- B. Cron-паблишер (05:50 UTC) публикует старые `summarized` статьи с
  `updatedAt=NOW()`, и старый пул содержит мусор, собранный до строгого
  классификатора (июльский Nature-фид).
- C. Хотфикс-сессия предыдущего агента внесла на сервере ручные правки
  `daily-digest.ts` (вырезка backticks, повреждение блока `okCount`) —
  файл рассинхронизирован с git, дайджест падал с `ReferenceError` и
  Telegram 400.

## Требования (директивы пользователя)

1. Формат превью для ВСЕХ разделов: `▫️ Название (@url:`URL`) — краткое описание`.
   Backticks вокруг URL — образец пользователя, сохранить.
2. Мусор без ИИ-сигнала — НЕ показывать: секция меняется только по правилу
   invention → science (AI-сигнал И науч. область) → иначе rejected
   (НЕ перенос в ai-news).
3. «За сутки» = последние 24 часа по `updatedAt`; июльские статьи уходят.
4. Сервер в состоянии, эквивалентном origin/main + пройденные тесты.
5. Тестовые отправки Telegram — только на ID 941296693 (владелец).
6. Клиенту отправка только после подтверждения владельца.

## Решение

- Т.01 Восстановить серверный `daily-digest.ts` из git main (вернуть okCount,
  backticks). Устранить REAL причину Telegram 400 (несбалансированные
  Markdown-сущности в реальных данных) — добавить в esc() недостающие
  символы/проверку, покрыть тестами.
- Т.02 Переписать backfill: неподтверждённые статьи -> `status='rejected'`
  (не перемещение в ai-news). Прогнать по published+summarized+pending.
- Т.03 Переклассифицировать пул `summarized` (источник завтрашних публикаций)
  до паблишера 05:50 UTC — мусор не выйдет в дайджест.
- Т.04 Деплой одним процессом (git clone -> npm ci -> build -> pm2 restart),
  health-проверка, тест-дайджест владельцу, после «ок» — клиенту.
- Т.05 Удалить сломанный backfill-скрипт предыдущего агента, заменить
  правильным; PROGRESS.md и трекер синхронизировать.
